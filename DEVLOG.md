## 2026-09-24
- Five more accounting gaps found and fixed after the audit below (uncommitted — pending review): (1) the project summary card's "paid %" divided raw totals, so an overpayment on one draw (e.g. $150k paid on a $100k draw) could mask a completely different, still-unpaid draw in the percentage even though the dollar figures were already correct — now caps each draw's own contribution at what it was actually billed for. (2) The retention-release calculation included other **draft** draws' `retainage_held`, which haven't actually been withheld yet, and could flip an already-negative balance (a prior over-release) into a new positive withholding instead of surfacing that as an inconsistency. (3) The monthly chart and the quarterly/annual billing report used different missing-date fallback chains (the chart tried `period_end` before `created_at`; the report skipped straight to `created_at`), so a draw with no `date_submitted` could land in a different month in each — unified into one shared `lib/billingDates.ts`. (4) `upsertDraw`'s edit path checked `deleted_at` but never verified the draw's `project_id` matched the submitted one — the one function in this file that hadn't gotten that check the last time around. (5) The G702 parser reads "Total Retainage" verbatim, which per the AIA standard is normally cumulative — but this app treats it as incremental everywhere, the same ambiguity that caused real trouble reconciling Hi Point last week. Deliberately did **not** touch the parser or any historical record for this one (that reconciliation already proved incremental is correct for HTA's actual documents) — just added an advisory caution on new uploads where the parsed value looks implausibly large relative to that draw's own billing. Added 25 more regression tests (90 total), including new Supabase-mocked tests exercising `upsertDraw`/`markDrawPaid`/`updateDrawStatus` and the AI write tools end to end, not just their shared helpers in isolation.
- Accounting-consistency audit turned up five real gaps, all now fixed and tested locally (not yet committed): (1) `markDrawPaid`/`updateDrawStatus` and their AI-tool equivalents defaulted a payment to `requested − paid`, ignoring `excluded_allocated` — the exact case this app was built to prevent (owner-paid subcontractor money being recorded as HTA's own cash received). (2) Billing Summary's "Outstanding" was actually billed-minus-received *within the selected year* — a period activity figure that goes negative for something like a December draw paid in January, not a real balance. Relabeled to "Billed − received" everywhere (hero, tables, mobile, CSV, the AI's billing tool) and added a genuine "Current Outstanding" figure (real per-draw collectible balances, portfolio-wide, not year-scoped) as the actual hero number. (3) The Monthly Billing chart and the project summary card's progress bar counted draft draws and owner-paid scope as billed, and lumped invoiced/paid into one shared date instead of grouping invoiced by submission date and paid by payment date — brought in line with the already-correct logic in `lib/billing.ts`. (4) Retainage-to-date and Balance to Complete summed a project's draft draws' `retainage_held` too, even though nothing's actually been withheld on an unsubmitted draft. (5) The AI's `updateDraw`/`markDrawPaid` tools (and the ordinary edit-draw/status/payment actions) could look up and mutate a soft-deleted draw with no `deleted_at` guard on the lookup *or* the write — now routed through a shared `getLiveDraw()` and enforced on both.
- Extracted the underlying math into pure, unit-tested modules where it wasn't already (`lib/monthlyBilling.ts`, `lib/projectSummary.ts`) and added 33 new regression tests across `lib/data.test.ts`, `lib/billing.test.ts`, `lib/monthlyBilling.test.ts`, and `lib/projectSummary.test.ts` — including the task's own worked example ($100k requested, $20k owner-paid, $30k received → $50k remaining), cross-year billing, overpayment-on-one-draw-masking-another, and trashed-record rejection. Full suite (65 tests), typecheck, lint, and build all pass clean.
- Root-caused a recurring live crash ("Minified React error #441") on the Add/Edit Draw form, seen twice this month on real saves (Gilmore Draw 9, a retainage check-constraint hit last session). Confirmed via a raw network response that Next.js strips `.message` off every thrown Server Action error in production — dev mode preserves it, which is why it never reproduced locally before. `upsertDraw` now returns `{ error }` instead of throwing, wrapped in a try/catch so nothing it doesn't anticipate can throw its way past that same redaction either; the client checks the returned value instead of relying on catching a rejected promise.
